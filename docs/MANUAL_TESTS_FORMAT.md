# Формат ручных тестов (manual)

## Обзор

Ручные тесты генерируются в виде структурированного текстового документа в формате Markdown, который QA-инженер может взять и выполнить вручную без кода.

## Структура тест-кейса

### Обязательные разделы

```markdown
# ТЕСТ-КЕЙС: [Название сценария]

**ID:** TC-001
**Приоритет:** CRITICAL | NORMAL | LOW
**Feature:** [Название фичи, если указано]
**Story:** [Название истории, если указано]
**Владелец:** [owner из запроса]

## 1. ПРЕДУСЛОВИЯ
- [Список условий, которые должны быть выполнены перед тестом]

## 2. ТЕСТОВЫЕ ДАННЫЕ
- [Данные, которые будут использоваться в тесте]

## 3. ШАГИ ТЕСТИРОВАНИЯ (позитивный сценарий)

| № | Действие (ACT) | Ожидаемый результат (ASSERT) |
|---|----------------|------------------------------|
| 1 | [Действие] | [Ожидаемый результат] |
| 2 | [Действие] | [Ожидаемый результат] |

## 4. НЕГАТИВНЫЕ / ГРАНИЧНЫЕ СЦЕНАРИИ
- **ГС-1 (Граничный):** [Описание]. *Ожидаемо:* [Результат]
- **НС-1 (Негативный):** [Описание]. *Ожидаемо:* [Результат]

## 5. ПОСТУСЛОВИЯ
- [Действия для очистки после теста]
```

## Пример полного тест-кейса

```markdown
# ТЕСТ-КЕЙС: Добавление сервиса Compute в калькулятор цен

**ID:** TC-001
**Приоритет:** NORMAL
**Feature:** Price Calculator
**Story:** Добавление сервиса Compute
**Владелец:** qa-team

## 1. ПРЕДУСЛОВИЯ
- Пользователь авторизован в системе Cloud.ru
- Открыта страница калькулятора цен (`https://cloud.ru/calculator`)
- Конфигурация пустая (0 ₽/мес)

## 2. ТЕСТОВЫЕ ДАННЫЕ
- Сервис: Compute (Виртуальные машины)
- Регион: Москва
- Конфигурация: 2 vCPU, 4 ГБ RAM

## 3. ШАГИ ТЕСТИРОВАНИЯ (позитивный сценарий)

| № | Действие (ACT) | Ожидаемый результат (ASSERT) |
|---|----------------|------------------------------|
| 1 | На главной странице калькулятора нажать кнопку "Добавить сервис" | Открывается модальное окно/страница с каталогом продуктов Cloud.ru |
| 2 | В каталоге в категории "Инфраструктура" выбрать продукт "Compute" | Карточка продукта "Compute" выделена. Кнопка "Выбрать конфигурацию" активна |
| 3 | Нажать кнопку "Выбрать конфигурацию" | Открывается страница конфигурации продукта Compute с полями: vCPU, RAM, Регион |
| 4 | В блоке конфигурации с помощью слайдера установить значение vCPU = 2 | 1) Значение слайдера обновилось на "2". 2) Блок "Итоговая стоимость" пересчитался (цена увеличилась) |
| 5 | Установить значение RAM = 4 ГБ | 1) Значение слайдера обновилось. 2) Цена в блоке "Итоговая стоимость" снова пересчиталась |
| 6 | Нажать кнопку "Добавить в конфигурацию" | 1) Сервис Compute появляется в списке "Мои сервисы". 2) Итоговая стоимость отображается рядом с добавленным сервисом |

## 4. НЕГАТИВНЫЕ / ГРАНИЧНЫЕ СЦЕНАРИИ
- **ГС-1 (Граничный):** Попытка добавить 100 экземпляров Compute. *Ожидаемо:* Поле ввода или слайдер ограничивает значение до 99, появляется сообщение "Максимум 99 экземпляров"
- **НС-1 (Негативный):** Попытка добавить второй сервис Free Tier. *Ожидаемо:* Кнопка "Добавить" для Free Tier неактивна, тултип "Free Tier можно добавить только один раз"

## 5. ПОСТУСЛОВИЯ
- Удалить все сервисы из конфигурации
- Итоговая стоимость вернулась к "0 ₽/мес с НДС"
```

## Формат файла

- **Расширение:** `.txt` или `.md`
- **Имя файла:** `manual_test_case_TC-001.txt` (где TC-001 - ID из тест-кейса)
- **Кодировка:** UTF-8

## Структура в JSON

```json
{
  "test_case": {
    "files": [{
      "description": null,
      "code": "# ТЕСТ-КЕЙС: Добавление сервиса Compute...",
      "filename": "manual_test_case_TC-001.txt"
    }],
    "raw_response": "[оригинальный ответ LLM]"
  },
  "test_type": "manual",
  "priority": "NORMAL",
  "owner": "qa-team"
}
```

## Отображение на фронтенде

- Показывать текст в отдельной вкладке или окне предпросмотра
- Возможность скачать как `.txt` файл
- Поддержка Markdown форматирования при отображении

## Требования к генерации

1. **Структура:** Обязательны все 5 разделов
2. **Таблица шагов:** Использовать Markdown таблицу с колонками №, Действие, Ожидаемый результат
3. **Метаданные:** ID, Приоритет, Feature, Story, Владелец должны быть заполнены
4. **Негативные сценарии:** Обозначать как ГС-X (граничный) или НС-X (негативный)
5. **Язык:** Всё на русском языке
